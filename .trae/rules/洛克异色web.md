# 适用场景：网页界面、后台管理页面、响应式布局开发

## 一、核心要求
1. 代码必须具备高可读性、高可维护性，结构清晰、模块化拆分，便于后期迭代修改
2. UI 设计遵循现代简约风格，美观、协调、高级感，符合主流前端审美
3. 严格遵循 HTML + CSS + JavaScript 分离原则，不混写、不冗余

## 二、代码规范
1. 命名规范：class、变量、函数、ID 全部使用语义化英文命名，禁止拼音、无意义命名
2. 缩进统一：使用 4 空格缩进，排版整洁，层级清晰
3. 注释规范：关键模块、复杂逻辑必须添加简洁注释，不写无效注释
4. 禁止使用：行内样式、滥用 !important、冗余嵌套、无效代码、废弃标签
5. 代码精简：无重复样式、无多余空行、无未使用变量与文件

## 三、UI 与样式规范
1. 配色：主色+辅助色+中性色搭配柔和，不刺眼、不撞色，支持浅色模式
2. 布局：居中对齐、等距留白、栅格系统，元素间距统一，不拥挤、不杂乱
3. 视觉效果：合理使用圆角、轻微阴影、平滑过渡动画，简约高级
4. 交互：按钮、输入框、卡片必须添加 hover / active 交互反馈
5. 响应式：兼容桌面端，布局不塌陷、内容不溢出

## 四、结构规范
1. 使用语义化标签：header、main、section、footer、nav、article 等
2. 页面结构模块化拆分，逻辑独立，便于复用与维护
3. 通用样式（颜色、间距、圆角）统一管理，方便全局修改主题
4. 表单、弹窗、列表、导航等组件结构标准化

## 五、JavaScript 规范
1. 逻辑简洁清晰，不写复杂难懂的代码
2. 避免全局变量污染，做好模块化处理
3. 交互逻辑稳定，无bug、无卡顿、无报错

## 六、禁止行为
1. 禁止生成杂乱、难以维护、冗余的代码
2. 禁止使用过时语法与废弃属性
3. 禁止 UI 风格割裂、配色混乱
4. 禁止结构与逻辑混写
5. 禁止生成无法直接运行、存在错误的代码

## 七、输出要求
1. 代码可直接运行，无需二次修改
2. 界面美观、交互完善、结构合理
3. 提供完整代码：HTML + CSS + JS
4. 模块划分清晰，便于后期扩展功能
5. 指出现在项目可优化和改进的地方
